# Database

Executable migrations: `0001_users_sessions_security.sql`, `0002_account_security.sql`, `0003_wallets_ledger.sql` (settings, wallets, ledger accounts/transactions/entries), `0004_payments_banks_withdrawals.sql` (payment orders, raw callbacks, payment review queue, bank accounts, withdrawals), `0005`/`0006` (campaigns, tasks), `0007_afrstar_callback_forwards.sql` (AfrStar hub log), `0008_appeals_reviewer_queue.sql` (appeal columns, review claims, reviewer actions, advertiser debts, `system:advertiser_receivable`, appeal settings), `0009_referrals_levels_notifications.sql` (referral codes and normalised emails on users, referrals, milestones, payouts, earner levels, notifications, notification preferences, announcements, `system:referral_bonus` / `system:referral_commission` / `system:bonuses`, Phase 6 settings). Placeholders still to come: `0010_virtual_number_orders.sql`, `0011_indexes_constraints_finalization.sql`.

Numbering note (Phase 6): the placeholders `0007_growth_referrals_bonuses_levels.sql` and `0008_notifications_announcements.sql` were deleted because 0009 implements them, and the old `0009_virtual_number_orders.sql` / `0010_indexes_constraints_finalization.sql` placeholders moved to 0010 / 0011, so each number has one file and the applied order on staging (…0007_afrstar, 0008_appeals, 0009_referrals) is unambiguous. Placeholders were never recorded in `schema_migrations`, so the renames need no database change. The interest catalog that the placeholder `0002_settings_catalog_interests.sql` reserved is implemented in 0009 (tables `interests`, `user_interests`, `campaign_interests`; setting `referrals.ip_allowance`), so that placeholder was deleted (it was never applied; 0009 was not yet on staging, so it was edited in place rather than adding a new migration). Files marked "NOT executable" are placeholders for later phases and are skipped.

`scripts/migrate.php` applies pending migrations once each, in filename order, and records them in `schema_migrations`. The cPanel release script runs it automatically before switching traffic. A database where 0001 was applied by hand is adopted without re-running it.

Manual run: `php scripts/migrate.php --config-dir=$HOME/yolotask-v2-live/config-private` (add `--status` to list pending files). Take a backup before migrating production.

First admin: `php scripts/create-staff.php --name="Full Name" --email=you@example.com --role=admin --config-dir=$HOME/yolotask-v2-live/config-private` emails a 48-hour set-password link.
