# Database

Executable migrations: `0001_users_sessions_security.sql`, `0002_account_security.sql`, `0003_wallets_ledger.sql` (settings, wallets, ledger accounts/transactions/entries), `0004_payments_banks_withdrawals.sql` (payment orders, raw callbacks, payment review queue, bank accounts, withdrawals), `0005`/`0006` (campaigns, tasks), `0007_afrstar_callback_forwards.sql` (AfrStar hub log), `0008_appeals_reviewer_queue.sql` (appeal columns, review claims, reviewer actions, advertiser debts, `system:advertiser_receivable`, appeal settings), `0009_referrals_levels_notifications.sql` (referral codes and normalised emails on users, referrals, milestones, payouts, earner levels, notifications, notification preferences, announcements, `system:referral_bonus` / `system:referral_commission` / `system:bonuses`, Phase 6 settings), `0012_leaderboard.sql` (leaderboard indexes on submissions and referral payouts, `leaderboard_rewards` history), `0013_deposit_cashback.sql` (`deposit_cashbacks`, `system:deposit_cashback`, settings `cashback.rate_bps` / `cashback.min_deposit_kobo`, both 0), `0014_withdrawal_fee_daily_checkin.sql` (withdrawal fee and daily check-in), `0015_leaderboard_all_time.sql`, `0016_custom_tasks.sql` (custom apps/sites/tasks with an advertiser-set price), `0017_retire_premium.sql` (premium campaigns and interests retired: premium catalog columns default 0, `task_reservations.unit_price_kobo` / `unit_reward_kobo`, `campaigns.repriced_at` and the matching `chk_campaigns_money`), `0018_afrstar_forward_registrations.sql` (AfrStar hub order registrations). Placeholders still to come: `0010_virtual_number_orders.sql`, `0011_indexes_constraints_finalization.sql`.

Numbering note (Phase 6): the placeholders `0007_growth_referrals_bonuses_levels.sql` and `0008_notifications_announcements.sql` were deleted because 0009 implements them, and the old `0009_virtual_number_orders.sql` / `0010_indexes_constraints_finalization.sql` placeholders moved to 0010 / 0011, so each number has one file and the applied order on staging (…0007_afrstar, 0008_appeals, 0009_referrals) is unambiguous. Placeholders were never recorded in `schema_migrations`, so the renames need no database change. The interest catalog that the placeholder `0002_settings_catalog_interests.sql` reserved is implemented in 0009 (tables `interests`, `user_interests`, `campaign_interests`; setting `referrals.ip_allowance`), so that placeholder was deleted (it was never applied; 0009 was not yet on staging, so it was edited in place rather than adding a new migration). Files marked "NOT executable" are placeholders for later phases and are skipped.

Numbering note (Phase 7): the leaderboard migration is `0012` rather than reusing a placeholder number. 0010/0011 stay reserved placeholders; the runner skips them without recording them, so on a fresh or existing database 0012 is applied straight after 0009. If 0010/0011 are implemented later they are still applied wherever they are pending (the runner applies every unrecorded file in name order), so nothing depends on the gap — keep later migrations independent of 0012 or number them after it.

Numbering note (deposit cashback): `0013_deposit_cashback.sql` is numbered after 0012 and depends only on 0003/0004 (ledger, settings, payment orders); it is applied straight after 0012. Verify with `database/verify/deposit_cashback_reconciliation.sql`.

Retiring premium (0017): the interest tables (`interests`, `user_interests`, `campaign_interests`) and the premium columns (`campaigns.tier`, `task_types.premium_price_kobo` / `premium_reward_kobo`, `earner_levels.premium_access`) are kept but unused, so the change can be reversed; drop them in a later migration once that is no longer wanted. After 0017 is applied, run `php scripts/retire-premium.php --config-dir=$HOME/yolotask-v2-live/config-private` once (add `--dry-run` first to preview); it is safe to run again.

`scripts/migrate.php` applies pending migrations once each, in filename order, and records them in `schema_migrations`. The cPanel release script runs it automatically before switching traffic. A database where 0001 was applied by hand is adopted without re-running it.

Manual run: `php scripts/migrate.php --config-dir=$HOME/yolotask-v2-live/config-private` (add `--status` to list pending files). Take a backup before migrating production.

First admin: `php scripts/create-staff.php --name="Full Name" --email=you@example.com --role=admin --config-dir=$HOME/yolotask-v2-live/config-private` emails a 48-hour set-password link.
